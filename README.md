# Помощник по ВКР

**Сайт:** https://mmarmar4028-gif.github.io/vkr-assistant/

Неофициальный помощник для бакалавров Высшей школы бизнеса МГУ (38.03.02 Менеджмент), которые пишут ВКР. Он **не пишет текст ВКР**, а берёт на себя рутину: сроки, план-график, чек-листы требований, список литературы, ссылки в тексте, нумерацию рисунков и таблиц, реестр допущений и рисков, шаблон Word.

Все требования взяты из Программы ГИА ВШБ МГУ на 2026-2027 учебный год. Рядом с каждым требованием указан номер пункта программы, чтобы его можно было сверить с оригиналом.

## Как пользоваться

1. Откройте ссылку на сайт и нажмите «Открыть помощник». Регистрация и пароль не нужны.
2. Начните с раздела «Профиль ВКР»: ФИО, тема, руководитель, формат работы. Эти данные подставятся в шаблон Word, заявления и план-график.
3. Изменения сохраняются сами, когда вы выходите из поля.

### Где хранятся данные

Всё, что вы вводите, хранится **только в вашем браузере на этом устройстве**. Ничего не отправляется ни на сервер, ни автору сайта, ни другим людям. Поэтому ссылкой можно спокойно делиться с друзьями: каждый видит только свои данные.

Из этого следует:

- **На другом устройстве или в другом браузере данных не будет.** Чтобы перенести их, скачайте резервную копию и загрузите её там.
- **Если очистить данные браузера** (историю, cookies и данные сайтов) или пользоваться режимом «Инкогнито», записи пропадут.
- **Если за компьютером работают несколько человек под одной учётной записью**, они увидят данные друг друга. На чужом компьютере в конце работы удалите данные в разделе «Резервная копия».

### Резервная копия

Раздел «Резервная копия»:

- **Скачать резервную копию** — один файл `.json` со всеми вашими записями. Делайте её время от времени, например после каждой встречи с руководителем.
- **Загрузить из копии** — восстановить данные из файла: на этом же устройстве после очистки браузера или на новом.
- **Удалить все данные** из этого браузера.

## Как устроена публикация

Сайт живёт на GitHub Pages и обновляется сам. После любого изменения в ветке `main` GitHub запускает проверку (файл `.github/workflows/pages.yml`): прогоняет тесты, собирает сайт и выкладывает его по адресу выше. Это занимает 2–3 минуты; ход видно во вкладке **Actions** репозитория. Если тесты не прошли, сайт не обновится, и останется прежняя рабочая версия.

Однократная настройка (уже сделана): **Settings → Pages → Build and deployment → Source: GitHub Actions**.

Серверов, баз данных и платных сервисов нет.

## Как обновить требования на следующий год

Все требования программы лежат в одном файле: `src/requirements/gia-2026-2027.ts`. Там сроки, ограничения объёма, структура, правила оформления, тексты форм и заявлений. У каждого правила есть поле `clause` с номером пункта.

1. Откройте на GitHub файл `src/requirements/gia-2026-2027.ts`, нажмите значок карандаша и исправьте всё, что изменилось в новой программе: даты в `DEADLINES`, год защиты в `PROGRAMME.defenceYear`, ограничения в `LIMITS`, тексты форм, номера пунктов.
2. Нажмите **Commit changes**. Через несколько минут сайт обновится сам.

Если хотите сохранить и старую версию требований, скопируйте файл под новым именем (например, `gia-2027-2028.ts`) и поменяйте одну строку в `src/requirements/index.ts`.

Если в программе изменился формат записей списка литературы или ссылок, правьте `src/lib/bibliography.ts` и `src/lib/citations.ts`, а эталонные строки — в `tests/bibliography.test.ts`.

## Спорные места программы

Там, где программа неоднозначна, приложение не угадывает, а показывает примечание:

- **Срок 15 апреля.** В Прил. 8 указан 2026 год; по порядку этапов это 2027. В приложении стоит 15.04.2027 с пометкой.
- **Размер листа.** В Прил. 7 написано «270 x 297 мм»; используется стандартный A4, 210 x 297 мм.
- **Отступ первой строки.** Указано «1,5» без единицы измерения; по умолчанию 1,5 см, значение можно изменить.
- **Название списка литературы.** В Прил. 5 — «Список использованной литературы», в п. 2.6 и Прил. 7 — «Список литературы»; используется второе.
- **Положение номера страницы** не задано; в шаблоне он внизу по центру.
- **Код EDN и ссылка на двух авторов.** Примеров в программе нет; запись формируется как `EDN: КОД`, а фамилии двух авторов перечисляются через запятую.

Все эти вопросы стоит уточнить у научного руководителя или в учебном отделе.

## Если когда-нибудь понадобятся аккаунты

Сейчас аккаунты не нужны. Но в проекте уже есть всё для версии со входом по почте, где данные хранятся в онлайн-базе Supabase и доступны с любого устройства:

1. Создайте бесплатный проект на [supabase.com](https://supabase.com). В разделе **SQL Editor** выполните содержимое файла `supabase/migrations/20261117000000_init.sql`: оно создаёт таблицы и включает Row Level Security («каждый видит только свои строки»).
2. В **Project Settings → API** возьмите **Project URL** и публичный ключ (**publishable** / **anon public**). Ключ **service_role** / **secret** никуда не вставляйте.
3. В репозитории на GitHub откройте **Settings → Secrets and variables → Actions → Variables** и добавьте переменные `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_ANON_KEY`.
4. В Supabase в **Authentication → URL Configuration** укажите адрес сайта: `https://mmarmar4028-gif.github.io/vkr-assistant/`.
5. Запустите публикацию заново: вкладка **Actions** → «Публикация на GitHub Pages» → **Run workflow**.

Учтите: данные, уже введённые в браузере, в базу сами не переедут.

Проверить, что пользователи не видят данные друг друга, можно командой `npm run check:rls-live`. Переменные для неё описаны в `.env.example`.

## Для разработчиков

Стек: Next.js (App Router, статическая сборка), TypeScript, Tailwind CSS, библиотека `docx`; Supabase — по желанию. Файлы Word собираются в браузере.

```bash
npm install
```

```bash
npm run dev
```

```bash
npm test
```

```bash
npm run build:pages
```

`npm run dev` запускает сайт на http://localhost:3000 (данные — в браузере). `npm run build:pages` собирает версию для GitHub Pages в папку `out/`.

Тесты (`tests/`):

- `bibliography.test.ts` — записи списка литературы сверяются с примерами Приложения 6 символ в символ; порядок, буквы после года, обязательные поля;
- `citations.test.ts` — ссылки в тексте по Прил. 7, пп. 13–17;
- `numbering.test.ts` — нумерация рисунков и таблиц, пересчёт после удаления и перестановки;
- `docx.test.ts` — оформление шаблона, тексты заявлений, анонимный экземпляр, план-график;
- `backup.test.ts` — формат резервной копии и сообщения об ошибках;
- `rls.test.ts` — для версии с Supabase: миграция выполняется в Postgres внутри процесса (PGlite); два тестовых пользователя не могут прочитать, изменить или подменить строки друг друга ни в одной таблице.

Структура:

```
src/requirements/     требования программы (единственный источник)
src/lib/              генераторы записей, ссылок, нумерации, файлов Word; хранение данных
src/components/       общие элементы интерфейса
src/app/(app)/        страницы разделов
src/app/(auth)/       вход и регистрация (только для версии с Supabase)
supabase/migrations/  схема базы данных и политики RLS (для версии с Supabase)
.github/workflows/    автоматическая публикация на GitHub Pages
tests/                тесты
```

## Чего в приложении нет

- генерации текста с помощью ИИ;
- хранения файлов ВКР — никакие файлы никуда не загружаются;
- автоматической проверки доступности ссылок — каждую ссылку проверяете сами и ставите отметку «ссылка проверена вручную».
